Banco de CORS del endpoint

Herramienta de desarrollo. No forma parte del sitio publicado.

La URL no se guarda. No se escribe en localStorage, ni en cookies, ni en la barra de direcciones. Al recargar, este campo vuelve a estar vacío.

Sírvela por HTTP. Abrir el archivo con doble clic (file://) da un origen null y el navegador aplica reglas distintas de las que tendrá el sitio real: el resultado no valdría.

Cómo leer el resultado

CORS OK — el navegador ha podido leer la respuesta desde este origen. Es lo que necesita el sitio.

BLOQUEADO POR CORS — la petición llegó al servidor, pero el navegador no deja leer la respuesta. El JSON puede ser perfecto: da igual. Hay que revisar el acceso del despliegue.

NO SE ALCANZA — la petición no llegó siquiera. URL equivocada, sin red, o el despliegue no existe. No es un problema de CORS.

RESPONDE PERO NO ES JSON — se pudo leer, pero el contenido no es el contrato. Suele significar que Google devolvió una página de error o de inicio de sesión: el despliegue no es accesible sin cuenta.

Cómo se distinguen

Cuando CORS bloquea, fetch falla sin decir por qué: el navegador oculta el motivo a propósito. Para separarlo de un fallo de red, este banco repite la petición con mode: "no-cors". Esa segunda petición no permite leer nada, pero sí distingue los dos casos: si la normal falla y la opaca funciona, el servidor está ahí y el bloqueo es de CORS.
